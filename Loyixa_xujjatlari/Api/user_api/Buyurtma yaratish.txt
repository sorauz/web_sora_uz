API Hujjati: Buyurtma yaratish (POST /order)
Servis: for_msp (1C:Предприятие 8.3.20)
Metod va URL: POST [http://1cloud.uz:777/SORA/hs/for_msp/order](http://1cloud.uz:777/SORA/hs/for_msp/order)Format: application/json; charset=utf-8Avtorizatsiya: 1C HTTP-servis uchun belgilangan Basic Auth (mavjud sozlamalar o‘zgarishsiz qoladi)

1. Oldingi versiyaga nisbatan asosiy o‘zgarishlar
Tashqi servis (frontend / backend) integratsiyasida quyidagi yangilanishlarni inobatga olish zarur:

Qaytariladigan javob kengaytirildi (201 Created): Mavjud message, order_number, order_id maydonlariga qo‘shimcha ravishda status_code, status, posted va total_amount maydonlari qo‘shildi (eski maydonlar bilan to‘liq mos).

O‘tkazilmagan hujjatda 500 o‘rniga 201 qaytadi: Avval omborda qoldiq yetmaganda yoki hujjatni o‘tkazishda (Проведение) muammo chiqqanda server 500 xato qaytarardi. Endi buyurtma chernovik sifatida saqlanadi va server 201 Created (posted: false, status_code: "PENDING") javobini beradi. Mijozga buyurtma qabul qilinganini ko‘rsatish va so‘rovni qayta yubormaslik kerak.

Qat’iy validatsiya kuchaytirildi:

Bazada mavjud bo‘lmagan GUID lar aniq tekshiriladi (404 Not Found).

1C da o‘chirishga belgilangan mijoz, kontakt yoki mahsulotlar rad etiladi (400 Bad Request).

quantity qat’iy 0 dan katta, price esa manfiy bo‘lmagan son bo‘lishi shart.

null qiymatlar endi 500 xato keltirib chiqarmaydi, to‘g‘ri validatsiya xabari qaytariladi.

Kafolatlangan JSON xato formati: Barcha 400, 404 va 500 javoblar har doim to‘g‘ri ekranlangan {"error": "..."} JSON formatida qaytadi.

4. Integratsiya bo‘yicha muhim qoidalar
Qayta yuborish (Retry) mantiqi: 201 javobida posted: false kelsa, bu xato emas — buyurtma 1C ga tushgan va order_id berilgan. So‘rovni qayta yubormang, savatchani tozalab xaridorga order_number ni ko‘rsating. Faqat tarmoq uzilishi yoki 500 da foydalanuvchiga qayta urinish taklif qilinadi.

Yakuniy summa: UI da buyurtma chekini chiqarishda server qaytargan total_amount qiymatidan foydalaning, chunki 1C qator summalarini 2 xona aniqlikda yaxlitlab hisoblaydi.

Statuslar mosligi: POST /order qaytargan status_code qiymatlari (CONFIRMED, PENDING) GET /order javobidagi status kodlari bilan bir xil — frontendda yagona status badge/rang xaritasini ishlatishingiz mumkin.
